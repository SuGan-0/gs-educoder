# 头歌课程实验工具（抓取 · AI 作答 · 自动提交）

把头歌（educoder.net）课程实验的题目抓成本地存档，用 **AI 或平台标准答案**生成答案库，
再由**篡改猴脚本**在关卡页自动作答、点「评测」、判通过后进入下一关。

三个组件各管一段：

| 组件 | 形态 | 职责 |
| --- | --- | --- |
| **extractor** | Node + Playwright（`npm run extract` / `npm run ui`） | 登录一次，把课程 → 课堂实验 → 关卡的题目正文、选项、初始代码、图片抓成本地存档 |
| **本地控制台** | `npm run ui`（只监听 127.0.0.1） | 驱动抓取；聚合答案库（AI 作答 / 平台标准答案回传）；给篡改猴提供答案、关卡映射、选项个数 |
| **篡改猴脚本** | Tampermonkey 用户脚本 | 在关卡页自动填答案、点「评测」、等结论、进下一关；支持教学课程队列批量推进 |
| **作业提醒** | `npm run reminder`（常驻服务） | 采集本人**进行中课堂**的课堂实验与图文作业，按截止时间提醒（本地文件或 Server 酱）；只读，不碰题目与答案 |

> **免责声明**：本工具只用于个人学习、备份自己有权限访问的课程内容。
> 自动作答与提交可能违反平台条款，使用风险自负；请勿用于刷课代做等用途。

## 快速上手

### 1. 安装

```powershell
npm install        # 依赖：playwright（Node 22，CommonJS）
npm run ui         # 启动本地控制台（自动开浏览器，终端打印带 token 的地址）
```

### 2. 登录一次

控制台里点「开始提取」会开一个独立 Chromium，在里面完成头歌登录。登录态存本地
`.educoder-browser/`，之后**不用每次重新登录**。

### 3. 抓题

控制台选 课程 → 实验 → 关卡，点「开始提取」。产物：

```text
exports/
├── answers/                                 ★ 答案库（AI 产出 + 平台标准答案回传）
│   └── 示例课程A__单元测试.answers.json
├── logs/                                    ★ 篡改猴脚本回传的运行日志
└── 示例课程A/
    └── 单元测试/
        ├── levels.jsonl                     # 关卡存档（唯一事实来源，每关一行）
        ├── 单元测试.md                      # AI 友好的题目正文（含每关「作答格式」）
        ├── 单元测试.metadata.json
        └── assets/L001-image-1.png
```

**只保留编程题与选择题**：虚拟机/图形化实操题（Logisim、StarUML、VNC 等）没有可
自动作答的环境，一律跳过并说明原因。

## 作业提醒：每天自动抓取 + 截止时间提醒

抓取范围是**本人进行中的课堂**（不是题目），两类作业都采：

| 类型 | 接口 `type` | 完成状态字段 |
| --- | --- | --- |
| 课堂实验 | `4` | `shixun_finished_status` |
| 图文作业 | `1` | `un_commit_work` |

截止时间**优先取精确的 `end_time_s`，其次 `end_time`**；补交时间 `late_time` 不当作正常截止时间。
状态无法识别时记为「未知」，**不会推断成未完成**（否则已交作业会被反复提醒）。

### 投递通道：提醒发到哪里

两种通道，**共用同一套去重记账**，随时可切换、数据不用迁移：

| 通道 | `REMINDER_CHANNEL` | 说明 |
| --- | --- | --- |
| **本地文件** | `local`（默认） | 不发手机。待办写成 `data/pending-reminders.md`，提醒流水追加到 `data/reminders.log` |
| **微信推送** | `serverchan` | 推到微信（[Server 酱](https://sct.ftqq.com) Turbo / ³），需要 `SERVERCHAN_SENDKEY` |

不设置 `REMINDER_CHANNEL` 时自动判定：有 SendKey 走 `serverchan`，没有则走 `local`。
所以**不填任何密钥也能先把整条链路跑通**。

> **本地通道适合谁**：不想注册推送服务，只想让服务在服务器上跑着、把待办整理成文件，
> 自己（或换个方式）去看。代价是**它不会主动叫你** —— 1 小时提醒只会写进 `reminders.log`，
> 你得自己打开看。要「到点就响」，请用 `serverchan`。

### 部署与运行

两种跑法，**共用同一套采集、快照与去重**，不必二选一：

| 方式 | 触发 | 适合 |
| --- | --- | --- |
| **DSH 自动化任务**（推荐日常用） | 每天 **8:00** 一次；到点时 DSH 没开着，就在下次打开时补跑 | 只在需要时看结果，不用常驻进程 |
| 常驻服务 `npm run reminder -- run` | 进程自己按间隔同步、分钟级检查 | 需要「到点就响」的 1 小时提醒 |

DSH 自动化任务每次只做两步：

```powershell
node --no-warnings extractor/reminder.js sync   # 抓取 + 刷新快照
node --no-warnings tools/deadline-digest.js     # 按固定规则出摘要
```

摘要规则（写在脚本里，不交给模型判断）：

- 只看 **48 小时内**截止的「待处理」作业；
- **已逾期的一律不列**；
- 已完成 / 已归档 / 未发布 / 完成状态未知，一律不列；
- **没有截止时间**的作业 → 给出该作业单（同一课堂）里**最近一个**未来截止时间。

登录态失效时它会明确报「请先 `npm run ui` 登录」，**不会编造截止时间**；
此时摘要仍可生成，但会标注「上次同步时间 + 数据可能已过期」。

常驻服务的形式如下（只有需要分钟级检查时才用）：

这是**常驻服务**，不是「每天跑一次」的脚本：1 小时提醒需要分钟级检查，
每天跑一次必然漏掉它。在服务器上让它长期运行（systemd / supervisor / pm2 均可），
进程被拉起后会自己按间隔同步。

```powershell
# 1) 复制配置模板并填写（.env 已 gitignore）
#    用本地通道：只需 UNDATED_REMINDER_MODE / QUOTA_POLICY（模板里已有默认值）
#    用微信推送：再填 SERVERCHAN_SENDKEY
copy .env.example .env

# 2) 确认登录态（登录态复用 .educoder-browser，与 npm run ui 共用）
npm run reminder -- auth-check

# 3) 采集一次并打印两类作业与截止时间
npm run reminder -- sync

# 4) 看当前待办（分档：已逾期 / 24 小时内 / 7 天内 / 更远 / 无截止时间）
npm run reminder -- status

# 5) 校验配置（不联网、不投递）
npm run reminder -- check

# 6) 预览「此刻该提醒什么」（不联网、不投递）
npm run reminder -- preview

# 7) 投递一条测试通知
npm run reminder -- test

# 8) 投递「未来 N 天截止」真实数据汇总，核对采集与截止时间算得对不对
#    （占一次额度，但不占正式的 24 小时 / 1 小时提醒名额）
npm run reminder -- test-upcoming --days=30

# 9) 正式运行（常驻）
npm run reminder -- run
```

> **运行 `run` / `auth-check` 前请先关掉本地控制台**（`npm run ui`）。
> 同一个 `.educoder-browser` 目录不能被两个 Chromium 同时使用，占用时会明确报错并提示。
>
> **服务器上只需要完整 chromium**：命令内部用 `channel: 'chromium'` 走新无头模式，
> 不依赖 `chrome-headless-shell`。装依赖用 `npx playwright install chromium`。

### 提醒规则

- **截止前 24 小时**提醒一次，**截止前 1 小时**再提醒一次；进入 1 小时窗口后**只发紧急阶段**，不叠加。
- **没有截止时间**的未完成作业按 `UNDATED_REMINDER_MODE` 处理：`once`（每个阶段只提醒一次）或 `daily`（每天一次）。
- 已完成、已归档、未发布、已截止的作业**一律不提醒**。
- **投递前复核**：真的要提醒时，只重新拉取涉及的课堂与作业类型——老师刚延期、学生刚提交都会立刻反映到内容里。
- **延期会重新提醒**：去重键包含截止时间与「被改过几次」，老师改期后是一个新事件。
- 重启不丢去重记录；同一条提醒在**同一截止时间、同一阶段**下只提醒一次。
- 投递失败按 5 分钟 / 30 分钟退避重试，单事件最多 3 次；微信通道有本地日发送上限（Turbo 免费通道最多 5 次）。
- 采集失败（分页不完整、结构异常、登录失效）**保留上一份成功快照**，不会写出半份结果，也不会误报「作业消失了」。

### 配置项

见 [.env.example](.env.example)。只有 `UNDATED_REMINDER_MODE` 与 `QUOTA_POLICY` 必填，
其余有默认值；`SERVERCHAN_SENDKEY` 只在使用微信通道时需要。

### 存储

| 路径 | 说明 |
| --- | --- |
| `data/reminder.sqlite3` | 作业快照、截止时间变更历史、同步时间、提醒去重与额度记账（Node 内置 `node:sqlite`，**不新增依赖**） |
| `data/pending-reminders.md` | **当前全部待办**（按紧急程度分档），每次同步后重写。本地通道下这就是你要看的那份 |
| `data/reminders.log` | **已触发的提醒流水**（追加），记录每次提醒的时间与内容 |
| `data/reminder.lock` | 单实例进程锁（PID 感知：进程已死或锁过旧会自动接管），防止 systemd 与手工命令同时跑导致重复提醒 |

`pending-reminders.md` 与 `reminders.log` 互补：前者答「现在还剩什么没做」，
后者答「什么时候提醒过什么」。只看一个都会看不明白。

题目存档（`exports/levels.jsonl`）与作业快照**刻意分开**：前者是一次写入、可重建的视图，
后者需要按主键更新、保留变更历史、做去重记账，两者读写模式不同，不强行统一。

## 签名常量（AK/SK）：是什么、怎么配

**这个项目必须配置它**——抓取和篡改猴脚本的课程/关卡读取，走的是头歌自己的 API，
每个请求都要带三个签名头：

```text
X-EDU-Timestamp: <毫秒时间戳>
X-EDU-Signature: md5(base64("method=GET&ak=<AK>&sk=<SK>&time=<同一个时间戳>"))
X-EDU-Type:      pc          ← 必须精确是 pc，写成 web 会被拒
```

- **AK（Access Key）/ SK（Secret Key）是什么**：拼进签名串的两个常量。服务端用同样的
  常量重算一遍签名，对得上才放行——相当于「证明这个请求来自头歌自己的前端」。
- **它们不是你的账号密码**：是头歌**前端 JS 里写死的公开常量**，所有用户同一对，
  从公开 CDN 的 `umi.<hash>.js` 里就能搜到（搜 `setHeader` / `getKey`）。
- 你的**账号凭据在 Cookie**（`_educoder_session`）里，与 AK/SK 无关。一个请求要成功 =
  正确的签名（靠 AK/SK）+ 有效的登录态（靠 Cookie）。
- **最容易踩的坑**：缺头或算错签名时，接口报的是
  `-102「服务器时间与您的设备时间不匹配」`——**这是误导信息，跟系统时间无关**。

### 怎么配置

| 入口 | 方式 |
| --- | --- |
| **篡改猴脚本**（浏览器侧） | **已内置，零配置**——装上就用。平台换常量时：菜单「**设置签名常量（平台换常量时覆盖内置值）**」粘贴新值覆盖（GM 存储优先于内置值），或更新脚本拿新的内置值 |
| **extractor / 控制台**（Node 侧） | 在仓库根建 `.educoder-keys.json`（已 gitignore）：`{ "ak": "<双 base64>", "sk": "<双 base64>" }`；或设环境变量 `EDUCODER_AK` / `EDUCODER_SK` |

> 粘错会在**保存那一刻**被拦住并说明原因（常量是双 base64，解两次后应是可打印 ASCII；
> 只粘「解过一次」的那串是最常见的错法）。不会等到接口报 `-102 服务器时间不匹配` 才发现——
> 那句报错跟时间无关，顺着它查会跑偏。

**获取方式**（仅在平台换常量、需要更新时才用）：浏览器打开任意头歌页面 → 开发者工具 → Sources/Network 找
`www-cdn.educoder.net/umi.<hash>.js` → 搜 `setHeader` / `getKey` → 两个双 base64 串。

**值放在哪**：

- 脚本源码里内置了一份缺省值（`educoder-autosubmit.user.js` 的 `EMBEDDED_SIGNING_KEYS`，10-14 起用户要求固化，免得每次重配）；
- 浏览器侧：篡改猴的脚本存储（键 `educoder-sign-ak` / `educoder-sign-sk`）——**存了的值优先于内置值**；
- Node 侧：仓库根的 `.educoder-keys.json`（每个工作区一份），内容就 `ak` / `sk` 两个字段。

**失效怎么办**：网站改版会换掉这对常量，届时所有请求重新报 `-102`。重新抓一遍
`umi.<hash>.js`，更新 `.educoder-keys.json`（或重新粘贴到菜单、更新脚本内置值）即可。常量变更日期见
`extractor/lib/educoder-sign.js` 里的 `SIGNING_VERSION`。

## 本地控制台界面说明

`npm run ui` 打开的页面（只监听 `127.0.0.1`）。布局按**干活顺序**排：

```text
顶部：标题 + 连接/阶段徽章 + 诊断、刷新状态
一行状态条：登录状态 · 当前阶段 · 状态说明 · 日志条数
左列（工作流）：提取（① 课程 → ② 实验 → ③ 关卡，一个面板装三步）→ 抓取进度
右列（结果与辅助）：AI 作答 · 缺答案清单 · 最近保存
底部：日志抽屉（常驻，收起时显示最新一条，点标题栏展开）
```

提取的三步是**顺序流程**，同一时刻只有一步是活的，所以合成一个面板、顶部一条步骤指示、
下面只显示当前这一步——而不是三个等高面板（其中两个永远锁着、白占半屏）。

几处刻意的设计，都是为了「一眼看到该看的」：

- **状态条压成一行**：原先这里是三张等高卡片，占掉首屏最贵的 ~90px，
  说的却都是顶部徽章与日志里已有的信息。
- **日志做成贴底抽屉**：它原来是页面最底部的普通面板，900px 高度的屏幕上根本滚不到，
  而它恰恰是抓取时最需要盯的东西。现在常驻可见，收起时一行显示最新一条（带级别色点）。
- **抓取进度紧跟在选择区之后**：窄屏（≤980px）时不再把整条右列挪到最后，
  否则「开始提取 / 停止」会被压到页面最底下。
- **深色模式跟随系统**：`prefers-color-scheme` 自动切换，无需开关。
  为此把 55 处硬编码颜色收敛成了语义变量（`--raise` / `--sunken` / `--ok-bg` …），
  深色模式只覆盖一层色板。
- **禁用按钮转灰**：以前只是 `opacity: .4`，实心群青透出来仍像「现在就该点它」。
  提示文案也改成「现在还不能选课程（当前正在：启动中）」，不再把内部状态名丢给用户看。

**① 抓取区（左列）**

| 控件 | 作用 |
| --- | --- |
| 课程 / 实验 / 关卡 三级选择 | 课程单选；实验、关卡多选，每级都有 **全选 / 反选 / 清空** |
| **跳过清单** | 本地已有的关卡（存档里有 / 答案文件里已有答案，比如抓过的或虚拟机题这类）会带绿色「**已有答案 / 已存档**」标签，**「全选」时自动不勾**——习惯全选的流程不用再手动挑。要重抓某一关，手动勾上即可；反选不受影响。列表上方会提示「跳过清单 N 关本地已有」 |
| 「重新下载已存在的关卡」勾选 | 默认关：内容指纹一致就跳过；勾上则强制重抓已存在的关卡 |
| **开始提取** | 启动独立 Chromium（首次在里面登录头歌）→ 按当前选择抓题 |
| **停止** | 引擎存活期间（等待登录、读课程/实验/关卡、抓取中）随时可停，已抓部分保留 |

**② AI 作答面板（右列）**

| 控件 | 作用 |
| --- | --- |
| **刷新产物** | 重扫 `exports/`，列出可作答的课程/实验/关卡，并显示每个实验「已有答案几关」 |
| 当前模型（只读） | 显示用的是哪个模型。**接口与 API Key 在 `.env` 里配**（`EDUCODER_AI_*`），界面上不填——界面上填的只活在内存里、关掉就没了 |
| **开始 AI 作答** | 逐实验把 `实验.md` 交给模型，答案写进 `exports/answers/`，并在面板里显示覆盖度与待修问题 |
| 停止 | 停掉正在跑的 AI 作答任务 |

**③ 进度与日志**：抓取进度（进度条 + 已保存/跳过/失败计数）在左列末尾；
实时日志在底部抽屉；最近保存列表在右列末尾。

**④ 页面顶部**：**复制控制台地址**（带 token 的完整 URL，粘给篡改猴用）；
**诊断**：在已打开的抓取浏览器里检查登录 cookie、接口原文响应、页面 DOM 与
时间偏差——抓不到数据时先点它，通常一眼能定位。

控制台**端口固定为 43127**（可在 `.env` 里改 `EDUCODER_UI_PORT`），token 持久化在 `.env` 里
（首次启动自动生成）。所以篡改猴**只需配一次**，之后控制台重启地址也不变——不用每次重配。

> 页面上**不再显示 token 与内部 API 路径**。之前页脚写着 `GET /api/state …` 和 token 前 8 位，
> 对使用者没有意义，也不该外露。

## 答案从哪来：两条路

### 路 A：AI 生成

先在 `.env` 里配好模型（`EDUCODER_AI_BASE_URL` / `EDUCODER_AI_MODEL` / `EDUCODER_AI_KEY`，见 [.env.example](.env.example)），
然后在控制台「AI 作答」面板：选课程/实验/关卡 → 开始。
逐实验把 `实验.md` 交给 OpenAI 兼容的 `/chat/completions`（默认
`https://api.deepseek.com/v1` + `deepseek-chat`，任何兼容接口都行），答案写到
`exports/answers/{班级}（{课堂码}）/{实验}.answers.json`，并立刻自校验（覆盖度、题型、
选项字母越界、占位代码）。API Key 只从 `.env` 读，不进仓库、不进日志，控制台界面也从不回显它。

写入走**合并**而不是重写：同一 `level_id` 覆盖，其它关卡原样保留，
所以只重答一关不会把人工改过的答案抹掉。

### 路 B：平台标准答案回传（更可靠）

**提交过一关之后**，平台的关卡数据里就有这一关的 `standard_answer`。篡改猴脚本可以：

- 「导出标准答案（本实验全部）」：从当前关沿关卡链逐关拉取，把整条链的标准答案一次回传；
- 每关通过后也会自动回传当关答案。

平台的标准答案是**按关卡**给的、且**只有提交过才有**；纯编程题没有标准答案
（平台不吐标准代码），这类只能靠 AI 或人工。

### 班级核对：不会把别班的答案填进去

同一个实验（同名、同关卡名）可能同时存在于多个班级里。答案文件带**课堂码**
（`classroom.code`，即平台的 `course_identifier`），三处都会核对：

- **落盘时**：文件里已有课堂码且与本次不同 → 拒绝写入（说明文件放错了目录）；
- **篡改猴回传时**：脚本报的班级与关卡存档不一致 → 控制台拒收；
- **篡改猴作答前**：答案的班级码与当前页面不一致 → **拒绝作答**并说明两边分别是什么。

班级从关卡数据里取（关卡页 URL 里没有班级码）。拿不到班级、或答案是老答案库时只提示不拦，
不会因为核对不了就把功能锁死。

### 缺答案清单

教学课程队列跑到「没有本地答案」的关卡时，会把关卡名记入缺答案清单并上报控制台
（`/api/missing`），跑完后按清单补答案即可，不会卡住队列。

## AI 答题：开发进度

> **答案库里的答案就是用 ZCode + GLM 5.3 写出来的**——AI 出答案这条路本身是通的。
> 但工具内置的「AI 作答」面板（从读题到落盘的一键链路）作者没有实际测试过，效果未经
> 实际验证；AI 写的答案也不保证全对，没通过的关卡以平台标准答案为准。

如实标注，不吹。

| 环节 | 状态 | 说明 |
| --- | --- | --- |
| 题目抓取（关卡存档 + AI 友好 md） | ✅ 完成 | `levels.jsonl` 单一事实来源；图片落 `assets/`；内容指纹去重；子标签实验支持 |
| AI 生成答案（OpenAI 兼容接口） | ✅ 完成 | 控制台「AI 作答」面板；答案自校验；`unanswered` 明细 |
| 答案库与关卡映射 | ✅ 完成 | `level_id` ↔ 平台标识；含「实验名__关卡名」「关卡名」两级兜底（平台换标识也能对上） |
| 篡改猴自动作答与提交 | ✅ 完成 | 选择题按分组勾选 / monaco 写入；点页面「评测」；**判通过才进下一关** |
| 教学课程队列（多实验多关卡） | ✅ 完成 | 存档续跑、跳过已通过、缺答案清单、日志落盘、卡住自检 |
| 平台标准答案回传 | ✅ 完成 | 单关 / 整实验批量；未提交过或纯编程题会明确列出 |
| 答案格式校验 | ✅ 完成 | `node tools/validate-answers.js`：覆盖度/题型/选项字母/占位代码 |
| **AI 答案的内容正确性** | ⚠️ 无保证 | 格式对了不代表能过评测——编程题可能跑不过，队列会停在那一关等你修 |
| **端到端全自动无人值守** | ⚠️ 受平台限制 | 评测不通过/超时会停队列（故意设计）；虚拟机与图形化题不参与；纯编程题无标准答案可回传 |
| 图片题理解 | ❌ 未做 | 图片会下载并嵌进 md，但发给模型的只有文本和路径，模型看不懂图 |

**一句话**：抓题、出答案、自动提交这条链是通的；瓶颈在**答案质量**——
最省力的实际用法是「AI 先答 → 通过的关卡自动回传标准答案 → 没过的关卡用标准答案重跑」。

## 数据格式：不是规范，可按需改

先说清楚：下面这些格式都是**作者的个人习惯**——为「喂给 AI、给篡改猴用」设计的，
不是什么规范，也不该被锁死。想改就改，每一条都给了**改的位置**。

### 抓取格式（题目存档）

| 产物 | 格式由谁决定 | 想改格式就改这里 |
| --- | --- | --- |
| `levels.jsonl`（每关一行） | 一行 JSON 的字段在 `toArchiveRecord()` | `extractor/lib/level-store.js` |
| `实验.md` 的小节模板（`### 任务描述` / `### 编程要求` / `### 初始代码` / `### 选择题` / `### 作答格式`） | 小节文案与拼装在 `task-parser.js` | `extractor/lib/task-parser.js` |
| `实验.md` 的分节与增量合并（`## 第N关：标题`） | 分节正则与合并逻辑 | `extractor/lib/extract-engine.js`（约 1957 行）；手动重建在 `tools/build-exports.js` 的 `buildOne()` |
| `实验.metadata.json` 的字段 | 同 `toArchiveRecord()` | `extractor/lib/level-store.js` |

改完记得 `node tools/build-exports.js` 重建视图；`实验.md` 是喂给模型的输入，
它的结构同时写死在 AI 提示词里（见下），两边要一起动。

### 答案格式

| 项 | 现在的样子 | 改这里 |
| --- | --- | --- |
| 答案文件名 | `exports/answers/{班级}（{课堂码}）/{实验}.answers.json` | `extractor/lib/answer-format.js` 的 `answerDirFor()` / `answerPathFor()`。旧扁平位置 `{班级}__{实验}.answers.json` **只读兼容**——用 `npm run migrate-answers` 迁到新位置 |
| 条目结构 | `{ level_id, task_identifier, title, kind, source, verified, answer }`；`answer` 编程题是 `{ language, code }`、选择题是 `{ questions: [{ number, selected }] }` | 同文件：`normalizeAnswer()` / `toDocumentEntry()` / `stringifyDocument()` |
| 选择题答案串 | 模型只写 `"A"` / `"A,C"` / `"1:A;2:B,D"`（题号:字母，多题分号，多选逗号）；**落盘是结构化小问数组** | 解析唯一一处：`answer-format.parseChoiceAnswer()`；篡改猴脚本的 `readAnswer()` 负责读 |
| AI 提示词（要求模型输出的 JSON 形状） | `{ "answers": […], "unanswered": […] }` | `extractor/lib/answerer.js` 的 `SYSTEM_PROMPT` |
| 校验规则 | 覆盖度 / 题型 / 选项字母越界 / 占位代码 | `extractor/lib/answer-validator.js` |

注意：答案格式是**三处契约**——答案文件 ↔ AI 提示词 ↔ 篡改猴解析，改一处要三处一起改
（`npm test` 里都有对应的用例，改漏了会红）。控制台「AI 作答」面板显示的覆盖度也按这套算。

另有一条**读取侧**的规矩：课堂码可以从答案目录名反解（`answer-format.classroomFromDirName()`）。
早期抓的关卡存档没有 `classroomCode` 字段，只靠存档算路径会得到**缺班级码**的位置
（`answers/{班级}/…`），与真实的 `answers/{班级}（{码}）/…` 对不上——表现就是
「答案迁到 v2 了却读不回来，旧扁平文件也不敢删」。所以凡是要算答案路径的地方
（`answerer.listTargets`、`validate-answers.js`、`check-answer-fit.js`）都必须留这一路兜底。

## 篡改猴脚本

> **只用脚本、不启动控制台** → 看 **[纯脚本使用文档](docs/USERSCRIPT-ONLY.md)**（装脚本 → 导入班级答案文件 → 一键答题，三步——签名常量已内置，不用配）。

> **两种版本**：完整版（下面讲）连控制台用；**简易版** [educoder-lite.user.js](userscript/educoder-lite.user.js) 只吃「班级答案文件」——完全不需要控制台与签名常量：导入文件 → 打开关卡页 → 一键答题（判通过才进下一关）。想把答案分发给同学，用简易版最省事（见「答案从哪来」的班级文件导出）。

| 步骤 | 操作 |
| --- | --- |
| 1 | 装 Tampermonkey，新建脚本粘贴 [userscript/educoder-autosubmit.user.js](userscript/educoder-autosubmit.user.js)——签名常量已**内置**，不用配 |
| 2 | 启动控制台 `npm run ui`（要连控制台才需要这步） |
| 3 | 菜单「**设置本地控制台地址**」粘一次 token（只粘 token 就行，端口固定 43127） |
| 4 | 面板「课堂」区：刷新课程 → 读取课程实验 → 勾选实验/关卡 → 一键答题（选中） |

**面板布局**（与控制台的「提取」面板同构）：

```text
标题栏（可拖动 / 右侧可收起整个面板）
步骤条：① 课程 ── ② 实验 ── ③ 关卡     ← 顺序流程，同一时刻只有一步是活的
[当前这一步的内容]                     ← 步骤条可点回去改，但跳不到还没走到的步
一键答题（选中）│ 停止 │ 按清单再答       ← 它们是同一件事的两面，放在一起
从本地加答案 │ 导出本实验全部答案 │ 导出日志到本地
评测最多等（秒）│ 关卡数据最多等（秒）
日志
```

面板整体可**收起**（标题栏右侧按钮，状态会记住）。其余低频操作（设置地址、导入答案、
清空进度、导出录制结果…）都在篡改猴菜单里。

**队列特性**：**只有判定通过才进下一关**（这条没有开关：提交未通过就停下并说明是哪一关）；
停在哪、下次点「继续答题（跳过已通过）」
就从哪继续；缺答案的关卡跳过并记账；答案**与这一关对不上**（题数不符，多半是答案过期或挂错）
的关卡同样跳过并记账——**不整队停**；点了「下一关」页面没跳转会重试并明确停队列。

**安全默认**：只有明确的「通过」才往下走；选择题页面题数与答案题数不一致就整体放弃勾选
（**一个选项框都不勾**，但没有答案可勾不该连累后面 100 多关，所以按「答案不可用」记账后继续）；
提交优先点页面自己的「评测」按钮，找不到才重放录制到的接口。

### 导出：两个入口，分工不同

| 入口 | 做什么 | 产出 |
| --- | --- | --- |
| **导出本实验全部答案**（面板按钮 / 菜单「回捞本实验标准答案」） | 沿关卡链逐关拉取**平台标准答案**（只有提交过的关卡才有），**写进脚本里的答案库（覆盖已有答案）** | **不下载文件**。按钮闪「✓ 已写入 N 关」，日志给一句总结（覆盖几关、新补几关、库里现在多少关） |
| **导出全部答案**（面板按钮 / 菜单「导出全部答案到本地文件」） | 把答案库**整份**导出成**班级答案文件** | 下载一份 `.json`，与「导入答案文件」**同一格式，可原样导回** |

两个都是「一键」，点哪个取决于你要的是「补齐答案」还是「拿走文件」：

```text
跑队列 → 通过的关卡自动回传标准答案
   ↓
想补齐剩下的 → 「导出本实验全部答案」（写进库里：已有答案的会被平台标准答案覆盖）
   ↓
想备份 / 换机器 / 传给同学 → 「导出全部答案」→ 得到 .json → 在别处「导入答案文件」
```

> **覆盖语义**：回捞到的平台标准答案**覆盖**库里已有的答案（它是判分依据，比导入来的那份权威），
> 不是「已有就跳过」。唯一例外：库里这一关已是**代码答案**时，不会被选择题标准答案盖掉
> ——一个条目只能存一种答案，覆盖会把代码弄丢；日志会明确列出这些关。
>
> 点完**一定会有反馈**：按钮临时变 `✓ 已写入 N 关` / `⚠ 拉到了但没写入` / `✗ 没拉到答案`，
> 日志同时给出成功或失败的原因（没导入过答案、没提交过、纯编程题没有标准答案等）。

> 导出**与导入严格同一格式**（都是 `kind: "class-answers"`）：班级块、每个关卡的
> `identifiers`（平台关卡标识）都会写回去，所以「导出 → 导入」是**往返一致**的
> （已有回归测试用真实答案库验过：155/155 关答案与标识一条不差）。

### 不连本地控制台也能用（控制台**可选**）

**一个入口**：面板按钮 / 菜单「**从本地加答案**」——

| 情况 | 行为 |
| --- | --- |
| 配了控制台地址且连得上 | 从控制台拉（顺带带回关卡映射、每题选项数、提交蓝图） |
| 没配地址 | 直接弹文件框，选一份班级答案文件导入 |
| 配了但连不上（控制台没开、端口变了）| 报一句原因后**自动退到选文件导入**，不再是死路 |
| token 不对（403）| 同上，提示重配地址并给出文件导入这条路 |

也可以直接用菜单「**导入答案文件（班级答案文件 / 控制台响应）**」——它认两种格式：

| 文件 | 来源 | 说明 |
| --- | --- | --- |
| **班级答案文件**（`kind: "class-answers"`） | `npm run build-class-answers`（**不用开控制台**），或控制台「导出班级答案文件」，或同学之间传 | **不用控制台**的首选：导入即可作答（班级 → 实验 → 关卡三层会被摊平成答题用的索引） |
| 控制台的 `/api/answers` 响应 | 控制台「复制控制台地址」后拉取 | 带 `levelIds` / `optionCounts` / `blueprints`，信息最全 |

> 导入失败一定会有**明确报错**，不会静默：文件没解析出答案时会把它的顶层字段列出来，
> 缺关卡映射（`levelIds`）时也会单独警告——这两种是「导入了却用不上」的常见原因。

**完整步骤（不连控制台）**：

```powershell
# 1) 终端里生成班级答案文件（读 exports/ 的工作层答案，与已有文件合并、不丢答案）
npm run build-class-answers        # 首次可加 --grade=2024级 --class=软工24-15、16班
#    产物：exports/answers/{年级}-{班级}.answers.json

# 2) 篡改猴 → 面板「从本地加答案」（没连控制台时会直接弹文件框）→ 选上面那份 JSON
#    日志会打印「班级答案文件已导入：… 现在共 N 关答案，可以不连本地控制台直接答题」

# 3) 篡改猴 → 菜单「设置签名常量（首次使用）」→ 粘一次 AK/SK（连控制台时脚本会自动同步）

# 4) 打开任意关卡页 → 面板「一键答题（选中）」
```

导入后可用菜单「**状态总览**」核对：应显示 `答案 N 关｜关卡映射 M 条`。

不连控制台时需要自己准备两样：

- **签名常量**：菜单「设置签名常量（首次使用）」粘一次 AK/SK（连控制台时脚本会自动同步，不用手粘）；
- **「每题几个选项」**：脚本优先读页面自己的关卡数据（最权威），所以这一项**不需要**控制台。

以下能力不连控制台时**会自动降级并明确提示**，不影响作答：日志上传到控制台、答案回传落盘、
缺答案清单上报。日志本身**只留在面板**（存脚本存储，刷新与关标签页都不丢），**上限 300 条**，
超出从头删——所以「不装控制台就一直攒着」也不会撑到配额。

## 路线 B：全部用篡改猴

> **状态：未实现。** 这节写给想把它做出来的人——是**实现地图**（数据从哪来、复用哪些
> 现成模块、要新写什么、坑在哪），不是使用说明。

### 为什么可行

- 脚本本来就在拦 `/api/tasks/{id}.json`——题目正文、编程要求、初始代码、选项、图片地址
  **都在这份 payload 里**（`observeTaskJson` 约 922 行处，现在只留了答题要的子集）；
- 调头歌 API 与 OpenAI 兼容的模型接口都**不受浏览器跨域限制**（`GM_xmlhttpRequest`）；
- 走关卡链的能力现成（教学课程队列就在这么走）。

### 要动的地方（按数据流顺序）

| # | 位置 | 要做什么 |
| --- | --- | --- |
| 1 | 脚本 `observeTaskJson` | 把**完整 payload** 留下来（现在只取答题字段），塞进一个待上报队列 |
| 2 | 脚本 图片 | payload 里的图片地址 → `GM_xmlhttpRequest` 拉 → base64（扩展名判断可参考 Node 侧 `detectImageExtension()`） |
| 3 | 脚本 → 控制台 | 新函数 `captureLevel()`：`GM_xmlhttpRequest` POST `/api/capture`（控制台在时走这里，不在时存 GM） |
| 4 | 控制台 `server.js` | 新端点 `/api/capture`（鉴权与 `readBody` 仿照 `/api/answer/save`） |
| 5 | 控制台 解析入库 | **复用现有模块**：`task-parser.js` 的 `taskFromApi()`（payload → task）→ `classifyTask()`（题型判据，自动剔除图形化/虚拟机）→ `level-store.js` 的 `toArchiveRecord()` + `appendLevel()` 追加 `levels.jsonl`；图片写 `assets/L00N-image-N.ext`（扩展名用 `detectImageExtension()`） |
| 6 | 视图 | `node tools/build-exports.js`（`buildOne()`，现成）；或直接调 `task-parser.js` 导出的 `makeExperimentDocument()` |

### 能省掉什么 / 要付出什么

- **省**：Playwright、npm、控制台进程、登录态 profile——装个脚本就能用，门槛低得多。
- **付**：数据住浏览器（换机靠导出导入）；图片 base64 吃 GM 存储配额（上限未实测）；
  控制台现有能力（缺答案清单、蓝图、日志落盘、AI 面板）要么重做要么放弃；
  脚本要加 `@connect` 声明（模型域名、`127.0.0.1`）。

### 坑（都有前车之鉴）

- **批量抓题的请求要带 `__easBatch` 标记**：批量拉标准答案时踩过——不带标记的
  `/api/tasks/*.json` 请求会被网络钩子当成「当前关」，污染 `state.taskContext`；
- `levels.jsonl` 是**追加制、最后一行生效**——只追加别重写，补抓才不会丢别的关卡；
- 图片文件名带关卡号（`L00N-image-N.ext`），同实验内不撞名；
- 图形化/虚拟机题的剔除判据在 `classifyTask()`——**复用它，别自己另写一套**
  （光看 `with_code_file=true` 会把 StarUML/Logisim 这类题误收）；
- 「AI 作答」若也走脚本，答案格式是**三处契约**（答案文件 ↔ AI 提示词 ↔ 脚本解析），
  改一处要三处一起改。

### 建议的落地方式

做成「控制台**可选**」而不是「替换」：脚本检测本地控制台在不在——在就照旧递数据
（抓题 payload / 答案 / 日志都走控制台落盘），不在就全存 GM。两条路线共用同一个脚本。

## 排查问题

| 症状 | 多半是 | 处置 |
| --- | --- | --- |
| 接口报 `-102 服务器时间不匹配` | **缺签名头或常量失效**（与系统时间无关） | 检查签名常量配置；网站改版则更新常量 |
| 答案拉到了但「没有本地答案」 | 关卡标识对不上 / 实验没抓过 | 看日志里的「关卡上下文」；重新抓该实验 |
| 「页面上找不到代码编辑器（等了 8 秒…现场：…）」 | Monaco 异步挂载没等到，或真没有 | 把括号里的现场发出来看：`monaco 模型 0 个` = 还没挂载/真没有 |
| 队列停在「评测超时」 | 评测跑得比等待上限久 | 调大面板「评测最多等（秒）」；已通过的关卡重跑会自动跳过 |
| 报「**答案里没有代码内容**」 | 库里这一关只登记了「是编程题」、没存代码（`answered:false`） | 现在**按缺答案处理**：记账 + 跳过，**不再停整队**（实测有 35 关属这类，以前每一关都能把队列停掉）。而「页面上找不到编辑器/提交按钮」是页面结构坏了，仍然停队——两类必须分开，混在一起就会要么漏做一整片、要么被单关卡死 |
| 报「**无法确定题目分组，已放弃勾选**」 | 本地答案与当前关卡**不是同一版**（多半这条答案挂在别的实验上） | 这类现在也**按答案不可用处理**：记账 + 跳过，不整队停。报错里会写明「页面/控制台读到几道题、答案几道题」——按两边题数即可确认。跑队列前先 `npm run check-fit`（这道关会不会被跳过）与 `node tools/validate-answers.js`（答案本身格式）各跑一遍；处置是重抓该实验后重新生成答案。**不要**去改「每题几个选项」的来源，那不是病因 |
| 报「**等了 N 秒、刷新重试 2 次还是没读到关卡数据**」 | 页面的 `/api/tasks/{id}.json` 没回来 | **两种要分开**：① 只是慢（页面还在加载）→ 脚本会等，等多久由面板「**关卡数据最多等（秒）**」决定（默认 60 秒），等待期间每 10 秒报一次；② **请求失败**（站点自己弹「本地网络不稳定…刷新后重试」、报 `Failed to fetch`）→ 等是等不到的（页面不会自己重发），脚本会**刷新页面重试，每关最多 2 次、两次之间至少隔 10 秒**，都救不回来才停队。（两处入口——进关卡后的续跑与开始作答前——共用同一套逻辑，别再各写一份：实测它们曾各写一份、行为不一，导致「等待设置不生效」） |
| 报「**无法定位实验「X」的入口关卡，已跳过**」 | 接口里还有这条作业记录，但课程页上没有它的入口 | **多半不是你的问题**：① 老师还没发布（读取阶段会直接滤掉并打一行「跳过 N 个未发布的实验」）；② 只对其他班级发布（同一课堂多个班）；③ 已从课程移除。日志的「章页卡片未找到的现场」会带上**本页可见的实验名单**，一眼能对出目标在不在 |
| 「卡片未找到」但实验明明在课程里（实验一多就出现） | 课程页的实验卡片列表**每页只渲染 20 张**，目标卡片在列表第 2 页 | 已修复：进实验改为**直达作业详情页**（`/shixun_homework/{作业号}/detail`，作业号本来就来自实验列表接口），不再依赖会分页的卡片列表；「章页找卡片」只作为详情页打不开时的兜底 |
| 提取时「选中 N 关，但关卡链上只到达 0 关」、所有实验的入口都是同一个「第 1 关」 | 入口解析吃了**别的实验**的关卡列表（多实验连抓时共享状态被最后一个实验覆盖） | 已修复：入口解析改用**本实验自己的**关卡列表（`resolveEntry`/`startPath` 显式传参）；串台防护（白名单拒收）仍然保留作第二道保险 |
| 报「**点了 X 页面既没跳转、也没能拿到目标地址**」 | 入口控件点不动（改版 / 被遮 / 合成事件没接上） | 日志会带上**当前路径 + 页面上可见的按钮**。若控件本来会开新标签页，先看有没有多出来一个标签页——队列可能在那边跑 |
| 「一键答题」时标签页越开越多 | 头歌的「开启挑战」「下一关」本身会开新标签页（一关一个） | 脚本会**强制改道到当前标签页**（点击期间临时接管 `window.open` 与 `target="_blank"`，点完还原）；万一还是被开走，旧标签页会**自动关掉自己**。浏览器只允许脚本关闭「脚本自己打开过」的标签页，所以用户最初那个关不掉，日志会说明 |
| 面板日志被清空看不清 | 落盘后自动清空（保留最后 5 行） | 看本地 `exports/logs/篡改猴日志.log`，那是全量 |
